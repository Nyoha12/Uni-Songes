# Uni-Songes public site content and layout audit — 2026

Status: read-only audit; no site correction is included in this PR.

Repository baseline: `release/prod` / `2c9f1fc5e20e2c5857745753a654fba1ad2b8169`.

Production origin used for observations: `https://unisonges.fr`.

**Scope, evidence, and limitations**

This audit separates two evidence classes throughout:

- **Rendered HTML observation** means an unauthenticated `curl` GET followed by
  offline parsing of the server response. The 20 requested paths were captured
  on 13 August 2026 between 20:25:06 and 20:25:39 CEST; related targets,
  `robots.txt`, and `sitemap.xml` were checked through 20:28:01 CEST. Redirects
  were followed. No form was submitted and no session was created.
- **Repository finding** means a conclusion supported by tracked source or
  configuration at the baseline commit. It does not prove that the same config
  object or entity revision is active in production.

This was not a browser audit. There was no JavaScript execution, screenshot,
viewport/responsive inspection, CSS box measurement, authenticated reservation,
cart mutation, checkout, form submission, accessibility-tree inspection, or
search-index inspection. “Visible text” below is an approximation from
server-rendered HTML after scripts and styles were excluded. CSS can hide it.
“Orphan” means no incoming link in the 20-page corpus, not no incoming link on
the whole web.

All 20 requested paths ultimately returned HTTP 200. `/` alone redirected once,
with HTTP 301, to `/accueil`; the other 19 were direct 200 responses. A 200
status does not imply that the page is complete or usable.

The repository inventory covered 12 node-specific Twig templates, all general
page/include templates, 64 block config names, 31 View config names, six menu
definition/override files, the custom module and its render arrays, the content
architecture and Commerce-offer scripts, the 2,508-line Drupal theme stylesheet, the legacy
`public/` tree, and route/product/pack/advanced wording. Relevant active-state
names were inspected read-only where exposed in HTML. The optional DDEV path of
the companion diagnostic was smoke-tested against the separate running local
project, but that database is not treated as a production content baseline. VPS
queries are supported by the diagnostic, but no VPS conclusion is made here:
non-interactive SSH credentials were unavailable.

Severity used below:

- **Critical**: blocks a required public journey or exposes a materially
  conflicting public journey.
- **High**: broken, empty, misleading, or non-reproducible public behavior with
  substantial user/operational impact.
- **Medium**: material inconsistency, discoverability, semantic, or maintenance
  defect.
- **Low**: contained polish or debt with no demonstrated blocked journey.

Proposed corrective PR codes (`B01`–`B12`) refer to the non-overlapping batches
in section 8.

### Reproduction commands

The companion script is read-only and defaults to repository-only mode:

```bash
cd drupal
./scripts/diagnose-public-site-content.sh
./scripts/diagnose-public-site-content.sh --public
./scripts/diagnose-public-site-content.sh --ddev
./scripts/diagnose-public-site-content.sh --ddev \
  --ddev-project-dir /path/to/an/existing/drupal-ddev-project
./scripts/diagnose-public-site-content.sh --vps --allow-vps
```

`--public` performs GET requests and clearly labels raw-HTML limitations.
`--ddev` uses Drush status plus SQL wrapped in `START TRANSACTION READ ONLY` and
`ROLLBACK`. `--vps` is refused unless `--allow-vps` is also supplied and uses
non-interactive SSH with strict host-key checking. None of the modes imports or
exports config, rebuilds caches, writes SQL, edits entities, deploys, pulls, runs
Composer, or changes DDEV configuration.
